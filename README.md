# Визуализатор зависимостей pip-пакетов — этап 3 (пункты 1–3)

Практическая работа №2, вариант №19. Приложение на Go
читает INI-файл, проверяет настройки и выводит их
в формате `ключ=значение`. В обычном режиме затем получает
и строит граф прямых и транзитивных зависимостей через JSON API репозитория.
Обход выполняется алгоритмом BFS без рекурсии: пакеты обрабатываются
в порядке добавления в очередь, каждый пакет загружается один раз.
Граф выводится списком смежности: `пакет: зависимость, зависимость`.
Пакеты без зависимостей также включаются в граф.

## Настройки

Все параметры обязательны и находятся в `[settings]`:

```ini
[settings]
package = requests
repository = https://pypi.org
test_mode = false
```

| Параметр | Назначение |
| --- | --- |
| `package` | Имя пакета |
| `repository` | URL репозитория или путь к файлу |
| `test_mode` | Тестовый режим: `true` или `false` |

В _обычном режиме_ имя содержит латинские буквы, цифры,
`.`, `_`, `-` и начинается и заканчивается буквой
или цифрой. Репозиторий задаётся URL с `http` или `https`.
В _тестовом режиме_ имя содержит только буквы `A–Z`,
а репозиторий задаётся доступным для чтения файлом.
В обычном режиме репозиторий должен поддерживать PyPI JSON API:
`GET /pypi/<package>/json`. Читается поле `info.requires_dist`;
для обхода из деклараций извлекаются имена пакетов.
Регистр и разделители `.`, `_`, `-` в именах нормализуются.
Ограничения версий и условия, включая extras, пока не вычисляются:
обходятся все перечисленные зависимости. Это граф деклараций,
который может отличаться от набора пакетов, устанавливаемых pip.
Используется только стандартная библиотека Go, тайм-аут запроса — 10 секунд.
В тестовом режиме граф читается из файла и обходится тем же алгоритмом BFS.
Циклы и самозависимости сохраняются в графе, повторный обход пакетов исключён.

По умолчанию используется `config.ini`.
Флаг `-config` выбирает другой файл.
Относительные пути считаются от рабочего каталога.
Пустые строки и отдельные комментарии с `#` или `;`
пропускаются. Значения указываются без кавычек.
Неизвестные, повторные и пустые параметры запрещены.

## Сборка и тесты

Требуется Go 1.27+. Запускать из корня проекта:

```bash
make build   # собрать bin/pkg-dep-vis
make test    # запустить тесты
make check   # тесты и проверки оформления
```

Для `make check` нужен `golangci-lint` в `PATH`.

## Формат тестового репозитория

Каждая строка описывает пакет и его прямые зависимости через пробел:

```text
A: B C
B: D
C: D
D:
```

Все имена состоят только из букв `A–Z`. Каждый пакет, включая пакеты
без зависимостей, должен быть объявлен отдельной строкой.
Пустые строки и отдельные комментарии с `#` или `;` пропускаются.
Повторные объявления, неверные имена и ссылки на необъявленные пакеты
считаются ошибками. Исходный пакет должен присутствовать в файле.
Весь файл проверяется, но в результат попадают только пакеты,
достижимые из исходного. Обращений к сети в тестовом режиме нет.

## Примеры запуска

```bash
make run ARGS="-config configs/online.ini"
./bin/pkg-dep-vis -config configs/test.ini
```

Для демонстрации трёх конфигураций из корня проекта:

```sh
sh scripts/demo.sh
```

Скрипт собирает программу и запускает её для `requests`, `idna`
и тестового репозитория. Первые два запуска требуют доступа к PyPI.
Для `idna` могут выводиться зависимости extras: условия пока не вычисляются.

Демонстрация трёх тестовых графов без доступа к сети:

```sh
sh scripts/demo-test.sh
```

`configs/test.ini` показывает транзитивные и общие зависимости:
`A: B, C`, `B: D`, `C: D`, `D:`.
`configs/test-cycle.ini` показывает цикл: `A: B`, `B: C`, `C: A`.
`configs/test-leaf.ini` показывает пакет без зависимостей: `A:`.

Вывод для обычного режима:

```text
package=requests
repository=https://pypi.org
test_mode=false
requests: urllib3
urllib3:
```

Список смежности выше сокращён для примера; фактический вывод зависит
от метаданных пакетов в репозитории.

Ошибки имени пакета, URL, режима, обязательных
параметров и файлов выводятся в `stderr`.
Код завершения: `0` — успех, `1` — ошибка.
Например, `package=-requests`, `repository=not-a-url`
или `test_mode=yes` приведут к ошибке проверки.

## Функции

| Функция | Назначение |
| --- | --- |
| `main` | Разбор флага и завершение процесса |
| `Run` | Загрузка, вывод и код завершения |
| `LoadDependencies` | Получение прямых зависимостей через PyPI JSON API |
| `BuildGraph` | Обход графа в ширину через очередь без рекурсии |
| `LoadGraph` | Построение графа по декларациям из PyPI |
| `LoadTestGraph` | Чтение тестового репозитория и обход через BFS |
| `parseTestGraph` | Чтение строк описания тестового графа |
| `addTestPackage` | Проверка и добавление объявления пакета |
| `validateTestGraph` | Проверка ссылок на объявленные пакеты |
| `normalizeName` | Приведение имён Python-пакетов к единому виду |
| `PrintGraph` | Вывод списка смежности по алфавиту |
| `LoadConfig` | Открытие, разбор и проверка INI |
| `parseConfig` | Чтение строк и контроль ошибок |
| `parseConfigLine` | Разбор секции или строки |
| `addSetting` | Добавление пары ключ-значение |
| `validateConfig` | Проверка параметров и режима |
| `validateRepositoryURL` | Проверка URL репозитория |
| `validateTestRepository` | Проверка тестового файла |
| `stringConfig` | Формирование вывода настроек |
